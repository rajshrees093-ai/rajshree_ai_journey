Architecture overview

Every round of this loop is a live, uncached call to the Claude API — nothing you see in the history panel is templated or computed with regex. The stop-check is the thing that governs information flow: after each Evaluator + Critic pass, three conditions are tested in fixed order — plateau (score gain below the configured delta for two consecutive rounds), threshold (score at or above your target), then the hard iteration cap as a safety fallback. Whichever fires first ends the loop and hands the latest draft, full history, and memory log to the Final Reviewer for sign-off. If none fire, the Improver receives the current draft plus that round's evaluation, critique, and accumulated memory, and produces the next draft — the round counter increments, and the cycle repeats.

Extension ideas

  • Add a Research agent that calls a search tool before Planner runs
  • Run Evaluator twice per round (rubric A/B) and average scores for stability
  • Persist memory + history to localStorage across sessions
  • Add a human-in-the-loop approval gate before Final Reviewer
  • Parallelize independent sub-tasks with multiple Executors
  • Swap the Improver for a diff-based patch agent instead of full rewrites

Prompts for building more advanced systems

"Add a branching planner that can choose between 2-3 different strategies before Executor runs, and score which strategy performed best." "Introduce a second, adversarial Critic that argues the opposite case, and have Improver reconcile both critiques." "Turn Memory Manager into a persistent vector-style store so future unrelated tasks can reuse learned preferences."
